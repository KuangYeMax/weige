# 商品场景图 MVP 设计

## 目标与边界

在本地提供一个单页工具，完成“商品原图上传 -> 通用事实卡 -> 人工编辑 -> 参考图生图 -> 结果落盘与下载”的最短闭环。默认使用完全离线的 mock provider；仅在用户明确配置火山方舟密钥、模型和 provider 后调用真实接口。

本 MVP 不包含账户、订单、消息、任务队列、多页后台、自动质检或火山之外的真实供应商。保真目标是一眼看出是同一商品并具有普通手机实拍感，不追求像素级复刻。

## 架构

FastAPI 同时提供 API、静态页面和受限的存储静态路由。业务按三条窄边界组织：Pydantic 负责品类无关事实卡校验；vision provider 只把图片变成事实卡；image provider 只接收参考图、短 prompt 和合法尺寸并返回已落盘的图片信息。产品和生成元数据保存为 JSON，避免为 MVP 引入数据库。

页面使用原生 JavaScript、Alpine.js CDN 和 Tailwind CDN。四个连续工作区对应上传、事实卡编辑、生成控制和结果，移动端改为单列。

## 数据与安全

除 `商品名称` 外，事实卡字段均可缺省并有空默认值；品类和关键结构均为自由数据。上传内容先按 10MB 限制读取，再由 Pillow 实际解码、修正 EXIF、检查最小边并转 RGB。文件和元数据一律使用 UUID/服务端路径，API 不接受本地路径。

所有错误返回统一的 `error.code/message/detail` 结构。密钥只在后端环境变量中；健康接口只返回配置状态。外部图片只允许 HTTP(S)，响应大小有限制，并立即保存到本地。图片和事实卡文本始终作为不可信数据进入固定模板。

## Provider 行为

mock vision 根据尺寸、主色和文件信息生成中性事实卡，不猜品类；mock image 在保留原图主体的基础上加简洁背景和明确角标。火山 vision 使用 Chat Completions 风格的多模态消息；火山 image 使用同步 images/generations 请求，并在 `image` 字段传参考图 data URI。网络层只对超时、429 和部分 5xx 最多重试两次。

## 测试与验收

pytest 覆盖健康检查、上传校验、通用 Schema、事实卡保存、mock 生成、404、未配置火山、静态目录穿越、尺寸映射和火山请求体。启动服务后再用真实浏览器完成桌面与移动端的上传、编辑、生成、下载入口和错误状态检查。

## 明确假设

- 需求附件即已批准设计，按其指定字段和文案实施。
- 当前目录为空且不是 Git 仓库，因此不初始化仓库、不创建技能要求的文档提交。
- 火山字段以其官方 `images/generations` 图生图示例中的 `image` 字段为准；模型 ID 始终由环境变量提供。
